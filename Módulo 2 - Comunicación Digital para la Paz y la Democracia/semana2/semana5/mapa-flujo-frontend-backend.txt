Completa el flujo con tus palabras.

1. Frontend

¿Qué parte del proyecto corresponde al frontend?

Respuesta: Corresponde a toda la interfaz interactiva y visual que se ejecuta directamente en el navegador del usuario final, compuesta en este caso por los archivos public/index.html (estructura), public/styles.css (diseño) y public/app.js (comportamiento lógico del cliente).

2. Backend

¿Qué parte del proyecto corresponde al backend?

Respuesta: Corresponde a la lógica de servidor que se ejecuta en segundo plano, administrada en este proyecto por el archivo server.js utilizando Node.js y el framework Express. Se encarga de recibir peticiones, leer la base de datos local y proveer respuestas HTTP estructuradas.

3. API propia

¿Qué rutas expone la API propia del proyecto?

Respuesta: Expone tres rutas GET para el consumo de datos: /api/mensajes (obtiene propuestas vecinales), /api/calendario (obtiene el plan editorial) y /api/resumen (despacha estadísticas del proyecto).

4. Datos

¿Qué archivos JSON usa el backend para responder?

Respuesta: Emplea archivos planos en formato JSON ubicados en la carpeta data/, específicamente data/mensajes.json y data/calendario-editorial.json, que funcionan como el almacenamiento de datos del mini-sitio.

5. Consulta desde frontend

¿Qué función de JavaScript se usa para consultar la API?

Respuesta: Se utiliza la función nativa fetch("/ruta-api") para realizar peticiones de red asíncronas en segundo plano de manera nativa y eficiente.

6. Espera de respuesta

¿Qué palabras se usan para esperar la respuesta del servidor?

Respuesta: Se utilizan las palabras clave de control de flujo asíncrono async (que declara que la función es asíncrona) y await (que detiene de forma limpia la ejecución de la función hasta recibir la promesa del servidor).

7. Conversión de respuesta

¿Qué hace respuesta.json()?

Respuesta: Deserializa el flujo de bytes en formato JSON recibido en la respuesta HTTP, transformándolo en un objeto o arreglo de JavaScript completamente legible y operable.

8. Render dinámico

¿Qué significa mostrar datos dinámicamente en el tablero?

Respuesta: Significa que las tarjetas no están precargadas estáticamente en el archivo HTML, sino que JavaScript recorre el arreglo de objetos recuperados del backend y construye en tiempo real los elementos visuales en el DOM de la página.

9. Prueba

¿Cómo verificaste que la información del tablero coincide con la API?

Respuesta: Editando directamente un mensaje en el archivo data/mensajes.json, reiniciando el servidor web y haciendo clic en el botón de carga del mini-sitio para confirmar que el nuevo texto apareciera de forma automática en la tarjeta del tablero.

10. Propósito comunitario

¿Cómo ayuda esta integración a mantener información comunitaria actualizable?

Respuesta: Al separar el almacenamiento de los datos de la interfaz visual, se permite que el contenido sea actualizado constantemente por los moderadores (añadiendo propuestas o cambiando fechas en el JSON) sin obligar a los programadores a modificar o redesplegar el código fuente del sitio web.
