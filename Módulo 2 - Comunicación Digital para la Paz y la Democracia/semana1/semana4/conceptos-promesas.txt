Responde con tus propias palabras.

1. ¿Qué es una promesa en JavaScript?

Respuesta: Es un objeto especial que actúa como un contenedor para el resultado de una operación que aún no ha terminado, pero que se resolverá en el futuro (asíncronamente). Representa un compromiso de entregar un valor de éxito o de reportar una falla de red.

2. ¿Por qué fetch devuelve una promesa?

Respuesta: Porque la solicitud HTTP de red no ocurre de manera instantánea; requiere que los datos viajen de ida y vuelta a través de internet o de la red local. Al devolver una promesa, fetch permite al navegador seguir respondiendo al usuario mientras espera los datos en segundo plano.

3. ¿Qué significa esperar una respuesta del servidor?

Respuesta: Significa que el programa cliente queda en un estado de espera activa, sin bloquear el resto de la interfaz, aguardando que el servidor procese la petición, lea o guarde los datos en el JSON, y devuelva una confirmación de éxito o un error de red.

4. ¿Qué hace .then()?

Respuesta: Es un método que se acopla a la promesa y define qué acción se debe tomar de manera automática en el momento exacto en que la promesa se resuelve exitosamente (es decir, cuando los datos del servidor llegan de forma correcta).

5. ¿Qué hace .catch()?

Respuesta: Es el método encargado de interceptar y gestionar cualquier error o falla que ocurra en el trayecto de la petición o dentro del flujo de los bloques .then(). Evita que la consola se inunde de excepciones incomprensibles y permite manejar el error de forma segura.

6. ¿Qué diferencia hay entre una respuesta exitosa y un error?

Respuesta: Una respuesta exitosa (promesa resuelta) significa que el servidor procesó el recurso y nos devolvió los datos requeridos. Un error (promesa rechazada) significa que el servidor está apagado, la dirección web está caída, la red no responde o que los datos enviados no pasaron las validaciones de seguridad.

7. ¿Qué hace respuesta.json() en esta práctica?

Respuesta: Toma la respuesta HTTP bruta proveniente del servidor, analiza su cuerpo de texto plano en formato JSON y lo convierte en un objeto de JavaScript estructurado. Dado que esta conversión toma tiempo, también devuelve una promesa que requiere otro .then().

8. ¿Qué pasa si el servidor no está funcionando?

Respuesta: El navegador no logrará establecer una conexión con la dirección ip o puerto. Por ende, la función fetch fallará de inmediato, la promesa se marcará como rechazada y el programa saltará directamente al bloque .catch() para manejar el incidente.

9. ¿Por qué una plataforma comunitaria debe mostrar errores comprensibles?

Respuesta: Para guiar a los vecinos con claridad y respeto en lugar de asustarlos con códigos de error crípticos. Si mostramos un mensaje comprensible, garantizamos accesibilidad, transparencia y reforzamos la confianza comunitaria en la herramienta digital.

10. ¿Cómo se relacionan promesas, fetch y API?

Respuesta: La API es el canal ordenado que expone el servidor. El cliente interactúa con esta API por medio del método fetch, el cual realiza la llamada de red y nos entrega una promesa que gestionará la llegada asíncrona de los datos a través de .then() (éxito) y .catch() (errores).
